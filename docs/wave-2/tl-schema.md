# TL bridge wire contract — version 1

This is the stable SDK/native boundary for wave 2. The Python SDK builds **data**;
the actual C BridgeBackend dispatches to Swift. No JVM object, pointer, reflection
handle, `debugDescription`, or invented Telegram field is a TL value.

## Calls and ownership

Use the existing bridge envelope:

```json
{"op":"call","fqcn":"exteraless.ios.Runtime","member":"tlRequest","args":[{"schemaVersion":1,"account":0,"request":{"_":"users.getUsers","id":[{"_":"inputUserSelf"}]},"timeoutMs":30000,"automaticFloodWait":false},{"__handle__":17}],"kwargs":{}}
```

The existing transport uses `call` for a static call, with no native instance.
`call_static` is not an operation in the actual C/native bridge. Callback markers may additionally
contain the existing `__fqcn__` / `__fqcn` string-or-null tags. Handles are positive
signed Int64 values owned by the calling interpreter. Create a **fresh callable
wrapper for each accepted operation**, even when reusing a plugin callback.

The C transport now injects `ownerToken` from its immutable per-interpreter state.
The native provider compares it with the captured owner's random `wireToken` on
admission/cancellation. It is not a caller-chosen capability. `value:null` in the
transport envelope is accepted. `exportedMethods` advertises the five operations
below without executing the provider for reflection queries.

- `tlRequest(requestModel, callback) -> {requestId: String}`.
- `tlCancel(requestId) -> {cancelled: Bool}`. Id belongs to this plugin **and
  interpreter generation**. Cancel disposes native work, suppresses its callback
  if cancel wins the terminal race, and releases the wrapper. Completed/unknown
  ids return false; a callback already handed to the owner dispatcher cannot be recalled.
- `getPeer(peerModel, callback) -> {requestId: String}`.
- `sendMedia(mediaModel, callback) -> {requestId: String}`.
- `editMedia(editModel, callback) -> {requestId: String}`.

The outer result is always the existing `{ok:true,value:...}` or
`{ok:false,error:{kind,message}}` envelope. Admission errors are synchronous and
**do not transfer the wrapper lease**; the SDK releases its wrapper on failure.
After admission Swift owns that lease until completion/cancel/unload/timeout.
Completion invokes method `run` with **exactly `[response, error]`**, one null:
`error` is `{"_":"error","code":400,"text":"RPC_ERROR_TEXT"}` for RPC errors.
Local terminal failures use code `-1`, text prefixed `EXTERALESS_` (including
`EXTERALESS_TIMEOUT` / `EXTERALESS_ACCOUNT_UNAVAILABLE`). No completion is emitted
for explicit cancel or plugin unload. Success is at most once; request admission
does not mean server delivery. Owner capture is synchronous before scheduling;
callbacks and handle release run on the captured owner's worker in FIFO order.
Native completion retains its quota slot until callback admission; cancel returns
false once completion has won, so the SDK must retain that lease until the callback
or an explicit owner-side native-handle release notification. Context teardown
finishes still-running requests with `EXTERALESS_ACCOUNT_UNAVAILABLE`.

`account` is a nonnegative Int32 **slot from TelegramPluginServices' snapshot**,
never an AccountRecordId cast. Pin its Int64 record at admission and resolve that
record on main before native use. Account switches cannot retarget an operation.
All models require `schemaVersion:1` and `account`. `timeoutMs` is optional,
default 30000, range 100…120000. No arbitrary callback args or Android connection,
datacenter, quick-ack or request flags are accepted.

`tlRequest` additionally accepts `applyUpdates: Bool` (default false), only for a
method whose declared result is `Updates`. True passes the **unmodified, native-
parsed** response to `AccountStateManager.addUpdates` before delivering its data;
the existing state manager owns pts/seq continuity. This explicit option is useful
for SDK edit helpers. Plain `send_request` remains a raw delegate API; high-level
text/media sends should use enqueue, including `sendMedia(kind:"text")` below.

## TL data

Canonical object: `{"_":"schema.constructorName", "schema_field": value, ...}`.
Method objects have the same shape with `"_":"namespace.method"`. Field names,
constructor IDs, result types and ordering come from the checked-in
`telegram-ios/submodules/TelegramApi/swift_scheme.tl`, **the native build input**.
`python/runtime/tl-schema.json` is generated by `tools/compat/generate_tl_bridge.py`.
The generated JSON has `schemaVersion`, `sourceSHA256`, `nativeLayoutHash`,
`constructors` and `methods` arrays. Each record has signed `id`, canonical `name`,
`kind` (`constructor|method`), ordered `params:[{name,type}]`, result `type`, and
`supported` (plus `unsupportedReason` on excluded records). `aliases` maps **actual
Android FQCN → canonical name**, `typeAliases` maps Android data base classes → TL
sum types, `fieldAliases` maps an Android FQCN → `{java_field: schema_field}` (for
example `_long → long`). `unsupportedAliases` enumerates known unmatched classes;
do not synthesize them from name similarity. Current generation: **1720
constructors, 860 methods (849 nongeneric), 2402 Android constructor aliases**.
`hookNames` maps canonical name → all actual Android `Class.getSimpleName()` values;
`hookAliases` is the inverse, with arrays because Java simple names can collide.
`preferredHookNames` picks an existing current alias for the callback's name argument.
SDK registration matching should accept canonical and registered Android names,
including substring matches, using these tables rather than a guessed `TL_` prefix.
Its explicit aliases map actual Android nested classes (for example
`org.telegram.tgnet.TLRPC$TL_users_getUsers`) to canonical schema names; class-name
guessing is not a substitute for the registry. Old-layer Android constructors
without a matching current wire layout must fail by name.

| TL field | JSON value |
|---|---|
| `int`, `#` | exact integer in signed Int32 (flags may also use unsigned UInt32 representation) |
| `long` | exact signed Int64 JSON integer; never float or truncated account/index |
| `double` | finite JSON number (not Bool) |
| `string` | UTF-8 JSON string |
| `bytes`, `int128`, `int256` | `{"__bytes__":"canonical base64"}`; fixed ints are exactly 16/32 wire-order bytes |
| `Vector<T>` | JSON array of T |
| named boxed type | recursive TL object of that schema result type |
| `Bool` | `{"_":"boolTrue"}` / `{"_":"boolFalse"}` (native accepts JSON Bool input too) |
| `flags.n?true` | JSON Bool, derived from its flags bit on decode |
| optional absent | omitted or null; decoded absent fields are omitted |

All schema `flags:#`/`flags2:#` are decoded as signed Int32. On encode a supplied
mask is authoritative: populated optional fields and Boolean flags must agree;
bit-enabled value fields must exist. Omitted masks are inferred from populated
optional fields / true Boolean flags. Fields sharing a bit must agree. Missing
Boolean flag fields can be inferred from an explicit mask. Unknown flag bits,
unknown fields, wrong result types and non-method requests fail explicitly.
No auto-filled random IDs, hashes, access hashes, pts, peer IDs or server fields.
Metadata (`constructor`, `networkType`, Java bookkeeping) stays in the Python
object layer, not the transmitted field dictionary.

For Android-facing callbacks a **top-level** `Vector<T>` response needs the SDK's
data wrapper for `org.telegram.tgnet.Vector` (`objects`, and primitive wrappers/
conversion helpers where applicable); the native wire stays a JSON array. Nested
vector fields are list/ArrayList data. This follows the actual `tgnet/Vector.java`,
not a fabricated TL constructor layout for the generic vector marker.

The codec checks boxed constructor/vector/Bool signatures, little-endian numbers,
TL byte/string length prefixes and padding, complete-buffer consumption, recursion,
vector/byte limits and schema type consistency. Requests/results are capped at
8 MiB binary, strings/byte fields at 4 MiB, vectors at 100000 elements and nesting
at 64, with 200000 total values. Bridge JSON is capped at 16 MiB. Inflight native operations are capped at
64 per plugin and 256 globally. Generic transport envelopes (`!X`, `X`, `Type`)
are named unsupported rather than submitted with a fabricated response parser.

## Peer lookup model

```json
{"schemaVersion":1,"account":0,"peer":{"type":"user","id":12345},"timeoutMs":30000}
```

`peer.type` is `user|group|channel|secret`, id is the positive raw Telegram ID (56 bits;
secret chat id must fit Int32). Secret targets are native encrypted-chat identities,
not a raw encrypted RPC recipe.
This is deliberately different from namespace-packed Postbox PeerId. Lookup is
local to the pinned account; a cache miss is a named failure, not a network fetch.
Success is a native snapshot:

```json
{"peer":{"type":"user","id":12345},"peerId":12345,"title":"Actual display title","inputPeer":{"_":"inputPeerUser","user_id":12345,"access_hash":9876},"inputUser":{"_":"inputUser","user_id":12345,"access_hash":9876},"cached":{"id":12345,"first_name":"Actual","last_name":"display title","bot":false},"partial":true}
```

`peerId` is namespace-packed Int64. `inputPeer`/`inputUser`/`inputChannel` are
present only when native cache data can genuinely construct them. `cached` is a
read-only **partial native-cache snapshot**, with Android-spelled data fields where
the meanings agree (`id`, `first_name`, `last_name`, `username`, `phone`, `bot`,
`verified`, `premium`, `deleted`, `title`, `date`, `participants_count`, `access_hash`,
etc., absent when not represented). It has no `_` constructor tag or invented TL
flags. Postbox does not preserve all fields required to reconstruct a User/Chat
(for example `bot_info_version`); therefore a cache snapshot must not be serialized
as a full TL object. Use `tlRequest(users.getUsers/messages.getChats/...)` for real
complete TL responses. `partial:true` makes this distinction machine-readable.

## Media model

```json
{"schemaVersion":1,"account":0,"peer":{"type":"user","id":12345},"kind":"document","path":"/absolute/plugin/cache/file.pdf","caption":"Caption","entities":[{"_":"messageEntityBold","offset":0,"length":7}],"silent":false,"replyTo":{"id":42},"timeoutMs":30000}
```

`kind`: `photo|document|audio|video|text|album`; `path`: existing local regular file accessible
under the caller's allowed file root (no URL downloader). Optional `caption`
defaults to empty, `entities` to empty, `silent` to false; optional `mimeType` and
`fileName` are document/audio/video metadata. `replyTo` is `{id: positive Int32}` in the
target cloud peer; optional `threadId` is a positive cloud topic id fitting Int32.
Optional `scheduleTime` is a positive Int32 Unix timestamp (including the native
send-when-online sentinel); it creates a real outgoing schedule attribute. Unknown fields fail.
Entities use the TL MessageEntity schema and UTF-16 caption offsets.
Completion reports **local enqueue**, not upload/server acceptance:
`{status:"enqueued",messageIds:[{peerId:Int64,namespace:Int32,id:Int32}]}`.
If native enqueue accepts only part of an album, status is `partiallyEnqueued`
and messageIds retains the original positions with null for rejected entries.
Swift uses existing native resource/upload/enqueue paths. Unsupported media,
entity, thread, paid-send or file cases fail by name before enqueue. Cancel cannot
recall a message after its Postbox enqueue has begun.

**Additive text variant:** `kind:"text"` uses `caption` as nonempty message text and
accepts the same entities/silent/replyTo/threadId/scheduleTime, plus
`disableLinkPreviews: Bool` (default false), with **no path/fileName/mimeType**.
It calls native `enqueueMessagesFromPlugin` with nil media. SDK rich-text helpers
should use it, so pending-message state and response Updates stay on the normal
outgoing pipeline; a raw `messages.sendMessage` RPC is a lower-level API and does
not by itself perform those native sender responsibilities.

File preparation is capped at **32 MiB**, two concurrent file preparations per
plugin and four globally. Photos become an orientation-correct native JPEG at
at most 1280 pixels (single-frame, source ≤64 MP). Audio/video duration and video
dimensions come from AVFoundation; video container support is mp4/mov/m4v. All
file/caption entities go through native upload/enqueue; missing metadata fails.

Additional v1 fields:

- `spoiler: Bool` (default false) creates the native media-spoiler attribute and
  reaches existing upload's InputMedia flags. Secret media have no spoiler field
  in SecretApi144 and are refused explicitly.
- `ttlSeconds: Int32?` requests native per-message expiration. Cloud: one private
  photo/video to another user, 1…60 seconds or `2147483647` (native view-once).
  Secret: 1…604800 seconds through native encrypted send; cloud view-once is not
  passed as a multi-year secret TTL.
- `replyTo.namespace: Int32?`: cloud defaults to `0`. Secret replies require an
  explicit `1` (Local/outgoing) or `2` (SecretIncoming), a cached message and its
  actual globallyUniqueId; no raw message-id-to-random-id guess.

For `kind:"album"`, `items` is an array of 2…10 item objects, each with
`kind:photo|video|audio|document`, `path`, optional fileName/mimeType/caption/entities/
spoiler/ttlSeconds. Root caption/entities must be empty and root spoiler/TTL absent;
root peer/account/silent/reply/thread/schedule apply to the whole batch. Photo/video
may mix; audio and generic-document albums each remain homogeneous. Total prepared
bytes ≤32 MiB. One real enqueue batch and one local grouping key preserve order and
use native multi-upload/send-multi-media. Cloud TTL albums are refused.

Secret sends use `enqueueMessagesFromPlugin`, secret-related local resources and
the existing ManagedSecretChatOutgoingOperations encryption/sequence machinery.
No scheduling or thread fields. Grouping requires negotiated layer ≥73; the
verified entity subset requires layer ≥144 (plain text/media do not require that
entity gate). Unrepresentable text mentions, bank/TON/date entities, nonempty pre
language and collapsed quote state fail by name rather than being dropped.

## Edit-media model

```json
{"schemaVersion":1,"account":0,"peer":{"type":"user","id":12345},"message":{"id":42,"namespace":0},"kind":"photo","path":"/absolute/plugin/cache/replacement.jpg","caption":"New caption","spoiler":true}
```

Same callback/deadline/ownership contract. `message.namespace` is Cloud `0` (default)
or ScheduledCloud `3`; only the latter accepts `scheduleTime`. Kind `text` keeps
existing media, while a file kind replaces it. A spoiler-only text-kind edit
reuses the existing native media reference. Omitted caption/entities/spoiler retain
the cached values; explicitly supplied text with omitted entities clears old text
entities. Secret edits, paid/rich-message replacement and uncached/uneditable targets
fail by name. Success is `{status:"edited",messageId:{peerId,namespace,id}}` only
after native `RequestEditMessageResult.done(true)`. Required-upload mode prevents
an upload failure from masquerading as a successful caption-only edit.
Hook-origin spoiler-only edits of an existing referenced media object currently
fail with `EDIT_HOOK_REFERENCE_UPLOAD_UNSUPPORTED`; that auxiliary revalidation
path has no per-invocation origin seam yet. New local-file edits use the explicit
upload-origin integration in `docs/tl-shared-integration.md`.

## Hooks: subwave-2 transforming contract

The old observation fallback remains explicitly `observational:true`.
`PluginTLObservationCodec.jsonString(event)` adds `tl` with the decoded real body,
`tlError` with the actual RPC error object when present, or a named `tlDecodeError`.
It retains all original metadata/bytes/observational fields. `hookName(canonical)`
uses the generated actual Android short class names. The SDK can expose `tl` as
the hook's deep TL object, keeping observation metadata in a separate read-only
attribute (outside the transmitted field dictionary).
Transforming paths use `PluginTLTransformPayload` with `observational:false`,
`phase:preRequest|postRequest|update|updates`, immutable `metadata`, actual `tl`,
`canCancel`, and optional read-only `tlError`. The SDK hook arguments stay the
original request/response/update/container TL data, with context kept outside TL
fields. JSON HookResult is `{strategy:"DEFAULT|CANCEL|MODIFY|MODIFY_FINAL",
request|response|update|updates: TLValue}`; `params` is an unambiguous alias.

- Pre replacements are complete schema-valid **same-method** request objects.
  Final account/privacy validation reads the replacement wire parameters.
  CANCEL is a terminal `EXTERALESS_PRE_REQUEST_CANCELLED` error; it cannot submit
  a request or invoke privacy willSubmit.
- Post replacements validate against the method result type, preserve continuity
  fields, and pass the original native response parser before delivery. RPC errors
  cannot be converted to fabricated success. CANCEL gives a terminal named error
  only for non-counter responses; state-bearing response cancellation is declined
  with a diagnostic. Semantic update cancellation belongs at the state barrier.
- Invalid replacement/native-parser rejection/timeout/detach explicitly keep the
  original and emit a named diagnostic. Pre admission overflow is a terminal error.
  MODIFY_FINAL stops the host's plugin chain. Every modification must be validated
  between plugins as well as at the final native boundary.
- Accepted updates run after global continuity acceptance and channel-ledger
  preflight. State versions are checked again before continuation and by the
  existing replay transaction. Cancellation suppresses semantic effects while
  preserving original global counters and channel counter-only carriers. Control/
  encrypted updates are read-only. Live containers retain actual provenance through
  grouping; partial/hole containers remain observational. Difference state/cache/
  encrypted fields are immutable. Container vector filtering is an ordered,
  unambiguous subsequence, retaining original references/counters.
- The same hook is not emitted observationally after a transform invocation.
  Hook waits are asynchronous, ≤5 s, FIFO per account/phase; native submissions also
  have an ordering barrier so asynchronous privacy lookups cannot reorder adds.
- Native hook ancestry is readonly context, not a field accepted in service models.
  Normal plugin calls still traverse request hooks. Calls/callbacks originating in a
  hook skip only ancestor plugins; depth-32 native effects fail explicitly. RPC post
  metadata retains timestamp/duration/networkType. Host queries real SDK priorities
  on captured workers and passes explicit `canonical_name` for response-hook matching.
