## IDS-01 — wall-clock expiry / monotonic wakeups

### Applied

- New `swift/ExteralessCore/Sources/ExteralessCore/IdentityExpiryTimer.swift` owns
  a wall-clock deadline and a cancellable one-shot monotonic wakeup. The wall
  clock and scheduler are injected. A callback is a **wakeup**, not evidence of
  expiration: it re-reads wall time, re-arms the remaining delay when early, and
  publishes when availability actually crosses the boundary.
- Generation checks reject callbacks queued before a reschedule. The owning
  account-cache lease token is checked before scheduling and publication.
  Invalidation cancels the timer and retires its generation.
- A backward jump after expiry can make the status active again according to
  the original wall-time semantics; the timer and presentation are renewed.
  Repeating an identical state/deadline at expiry cannot consume an unpublished
  boundary. A genuinely changed deadline is established by its state publication.
- `TelegramCore/Sources/ExteralessIdentity/ExteralessIdentityPresentation.swift`:
  the ordinary `ExteralessIdentityAccountLease(account:)` uses this driver with
  `Date().timeIntervalSince1970` and the existing `SwiftSignalKit.Timer`.
  `refreshExpiration()` is the main-queue lifecycle entry. The existing token,
  account validation, publication sequence and state dedup remain in the path.
- `TelegramUI/Sources/ExteralessClient/Identity/ExteralessIdentityIntegration.swift`:
  foreground and significant-time-change both call `refreshExpirations()`, which
  rechecks **every retained account lease** and refreshes date presentation.

The native lease also has a dependency-injected initializer taking an account ID,
state signal, fresh publication cache, wall clock, monotonic scheduler and
publication callback. It executes the same native path without constructing an
Account, Postbox or network. A rejected foreign state cannot install its deadline.

### Meaningful fixtures

`swift/ExteralessCore/Tests/ExteralessCoreTests/IdentityExpiryTimerTests.swift`:
**9** synchronous virtual-clock cases cover:

1. the review's backward-jump/early-callback counterexample without a notification;
2. backward-jump notification and stale cancelled callback;
3. forward jump before expiry shortening the monotonic deadline;
4. forward-past-expiry and backward revival;
5. suspension and foreground before an overdue callback is delivered;
6. a new status retiring the previous deadline;
7. identical snapshot arriving exactly at expiry;
8. account retirement;
9. nil/zero/disabled expiry.

`telegram-ios/Tests/Exteraless/IdentityRemediationTests.swift`:
**4 native lease cases** use the real publication cache and native peer projector
with separate injected wall/monotonic clocks. They check the rendered document
becomes nil at the real boundary, stored status is retained, lifecycle refresh
re-arms, suspension cancels stale wakeups, replacement account tokens survive old
callbacks/deinit, and foreign state is rejected. **No system clock is changed.**
